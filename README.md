# Oracle Docker Colav

Oracle docker Colav is a set of packages that allows to deploy Oracle express in a docker container to work with the multiples databases and from Colav and its parners.

## Automation Framework (Scienti Workflow)

A modular automation system has been incorporated that:

- Downloads dumps from Google Drive
- Dynamically generates configuration files (`.env`)
- Spins up Docker containers (Oracle + MongoDB)
- Loads dumps into Oracle XE
- Executes **Kaypacha** to extract data
- Stores the final result in MongoDB
- Automatically finalizes and cleans up containers

The automation runs from the entry point:

```
/automation/main.py
```

---

## Environment Variables

To use the automation system, you must create a **`.env`** file in the project root.

### Example `.env`

```env
GOOGLE_CREDENTIALS=./automation/token.pickle  # DO NOT modify
GOOGLE_PARENT_ID=<your_google_drive_folder_id>
```

### Variable Descriptions

#### `GOOGLE_CREDENTIALS`

Path to the Google Drive credentials file.  
⚠️ **Should not be modified.**

#### `GOOGLE_PARENT_ID`

ID of the Google Drive folder containing the Scienti dumps to process.

These variables are automatically loaded by the automation framework.

---

## Data Extraction with Kaypacha and MongoDB

During the execution of `/automation/main.py`:

1. A MongoDB service is created via `docker-compose`
2. Kaypacha runs inside the Oracle container after loading the dumps
3. The extracted database is stored in MongoDB using the dynamic name generated by Kaypacha
4. Data is persisted in a Docker volume for MongoDB, which means:
   - Data is not lost when containers are stopped
   - Can be queried later using `mongosh` or other tools
